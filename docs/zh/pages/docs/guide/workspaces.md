# 工作区

此页面是模态工作区的高级指南，
Modal 资源的主要组织单位
和认证。

**工作区**是用户可以部署模态应用程序和其他应用程序的区域
资源。当您注册 Modal 时，会自动创建一个工作区
你。它的名称基于您的 GitHub 用户名，但可能是随机生成的
如果该名称已被占用或无效。

每个工作区都是共享的，这意味着您可以通过电子邮件邀请其他人
与您合作。

<Callout variant="info">

较旧的帐户可能有一个单成员“个人”工作区，但没有
支持邀请更多成员。展望未来，所有新注册均以
一个普通的工作空间，一旦您验证了您的身份，就支持邀请队友
帐户通过添加付款方式。

<br />

现有工作空间不受影响，计划或计划没有任何变化
定价。

</Callout>

## 创建工作空间

有两种方法可以在
[设置](/settings/workspaces) 页面。

<Callout variant="info">
如果您的 Modal 帐户是通过 Okta 配置的，您将无法选择创建新的工作区。您的工作区由组织的 Okta 配置管理。如果您需要新的工作区，请联系您组织的 Okta 管理员。

</Callout>

![工作区创建界面视图](https://modal-cdn.com/cdnbot/create-new-workspace-viewk0ka46_7_800f2053.webp)

1. 从[GitHub组织](https://docs.github.com/en/organizations)创建。允许 GitHub 组织的成员自动加入工作区。

2. 从头开始​​创建。您可以邀请任何人加入您的工作区。

如果您有兴趣拥有与您的 Okta 关联的工作区
组织，然后查看我们的 [Okta SSO 文档](/docs/guide/okta-sso)。

要通过 Google 或其他提供商使用 SSO，请通过 <support@modal.com> 联系我们。

## 自动加入与 GitHub 组织关联的工作区

注意：这仅与从 GitHub 组织创建的工作区相关。

如果用户是与工作区关联的 GitHub 组织的成员，则可以在其[工作区设置页面](/settings/workspaces) 上自动加入该工作区。

要关闭此功能，工作区管理员可以在其工作区设置页面的 **工作区管理** 选项卡上禁用它。
## 邀请新的工作区成员

要邀请新的 Workspace 成员，您可以访问[设置](/settings) 页面
并导航至相应工作区的“成员”选项卡。

您可以发送电子邮件邀请或共享邀请链接。现有模态
用户和还没有 Modal 帐户的人可以使用链接加入
您的工作空间；如果他们没有帐户，我们会为他们创建一个帐户。

邀请会员需要经过验证的帐户。如果您还没有添加，请添加
验证您帐户的付款方式。

![邀请会员部分](../../assets/screenshots/invite-member.png)

## 为工作区创建令牌

要以编程方式与工作区的资源进行交互，您需要添加
该工作区的 API 令牌。您现有的 API 令牌显示在
[设置页面](/settings/tokens) 和新的 API 令牌可以添加
特定的工作空间。

将工作区的令牌添加到模态配置文件后，您可以激活
使用 CLI 访问该工作区的配置文件（见下文）。

作为管理者或工作区所有者，您可以管理工作区的活动令牌
[会员令牌页面](/settings/tokens/member-tokens)。有关 API 的更多信息
代币管理参见
[有关配置的文档](/docs/sdk/py/latest/config)。

## 切换活动工作区

在仪表板上或使用 CLI 时，活动配置文件确定哪个
工作区与您的操作相关联。

### 仪表板

您可以使用工作区选择器在工作区之间切换
[仪表板](/home) 顶部。

### 命令行界面

要切换与 CLI 命令关联的工作区，请使用
`modal profile activate`。

## 管理工作区成员资格

工作空间具有三种不同级别的访问权限：

* 业主
* 经理
* 会员

创建工作区的用户会自动设置为该工作区的 **所有者**
工作区。所有者可以分配工作区中的任何其他角色，以及
删除工作区的其他成员。

工作空间中的**经理**可以分配除**所有者**之外的所有角色，并且可以
还删除工作区的其他成员。

工作空间的**成员**不能在工作空间内分配任何访问权限
工作区，但可以执行任何操作，例如运行和部署应用程序
并修改 Secret。

作为所有者或经理，您可以管理其他人的访问权限
[设置](/settings/workspace-management) 中的 `Workspace Management` 选项卡上的成员。

<Callout variant="info">

Modal 支持[基于角色的访问控制 (RBAC)](/docs/guide/rbac)，以便对工作区和环境级别的权限进行更精细的控制。

</Callout>

## 离开工作空间

要离开工作区，请导航至[设置页面](/settings/workspaces)，然后
在列出的工作空间上单击“离开”。如果您是工作区，则无法离开该工作区
唯一剩下的成员。如果您是仍然拥有的工作区的最后一个所有者
其他成员，在离开前指定一个新的所有者。个人工作区是
单身成员，所以他们不能离开。
