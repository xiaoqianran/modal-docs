# 功能成熟度

Modal 的新功能经历了几个阶段的演变。为了帮助您了解它们的稳定性，我们使用两个独立的概念：

* [发布阶段](#release-phases)（[Alpha](#alpha)、[Beta](#beta) 或 [GA](#general-availability-ga)）：表示功能底层基础设施的稳定性
* [Experimental SDK](#experimental-sdk): 代码接口中信号 API 稳定性

即使我们仍在改进后端功能的性能或扩展，这种分离也使 SDK 能够保持稳定。

## 发布阶段

我们使用以下发布阶段来表示功能的底层设计和基础设施的成熟度：

### 阿尔法

Alpha 保留用于可能仍然脆弱且具有已知限制的功能。我们很早就提供了这些，以便您可以进行试验，但您应该预料到该功能的工作方式会发生重大变化。文档会清楚地说明它们的局限性。

某些 Alpha 功能是私有的，这意味着您需要联系我们才能访问。

### 测试版
Beta 是我们新功能的默认阶段。 Beta 功能通常是自助式的、实用的，而且大多是稳定的。 Beta 功能通常适合生产使用，尽管我们可能仍在完善最终的行为、定价或规模限制。

某些测试版功能是私有的，这意味着您需要联系我们才能访问。

### 正式发布 (GA)

GA 功能稳定且完全适合生产级使用。没有计划进行重大更改。 Modal 文档中未标记为 Alpha 或 Beta 的任何功能都可以视为 GA。

## 实验SDK

除了上述发布阶段之外，您可能会看到 Modal SDK 的某些部分被标记为实验性（例如，`_experimental_snapshot()`）。

这严格来说是一个 SDK 概念，表明 API 稳定性，而不是基础设施成熟度。它通常与 Alpha → Beta → GA 进程相关，但并非总是如此。某些功能在后端仍处于成熟阶段时就很早就稳定了其 API，但实验性 API 也可能会在功能生命周期的后期引入，以提供额外的配置深度。
实验性标签意味着我们仍在收集反馈并迭代接口：方法名称、参数或返回类型可能会发生变化。一旦我们对设计充满信心，我们就会删除实验标记并致力于向后兼容。

## SDK 弃用

通过 SDK 中的稳定 API 公开的功能可能会被“弃用”，这要么是因为我们停止支持相关平台功能，要么是因为 API 正在调整，例如减少持续的混乱或适应意外的扩展。

已弃用的 API 将保持功能并发出弃用警告。我们建议您注意这些警告，因为弃用最终将被强制执行，并且使用已弃用 API 的代码将被破坏。重大更改仅限于我们的 `X.Y.Z` 版本控制方案中的 `Y` 版本的增量。

## 其他接口

目前只有官方 SDK 被认为是稳定的。任何其他公共接口均未记录，如有更改，恕不另行通知，使用风险由您自行承担。
