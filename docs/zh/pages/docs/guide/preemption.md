# 抢占

默认情况下，所有模态函数都会被抢占。
如果抢占事件中断了正在运行的 Function，Modal 将正常终止
函数并在同一输入上重新启动它。

抢占很少见，但您的函数总是有可能
打断了。长时间运行的函数，例如模型训练函数应该采取
特别注意容忍打扰，因为打扰的可能性会增加
与函数运行持续时间。

## 为中断做好准备

将您的应用程序设计为容错和抢占。模态将发送一个
当发生抢占时向容器发出中断信号。这将导致
要运行的函数的 [退出处理程序](/docs/guide/lifecycle-functions#exit)，其中
可以在其宽限期内执行任何清理。

处理抢占的其他最佳实践包括：

* 将长时间运行的操作划分为小任务或使用检查点，以便您
  可以经常保存您的工作。请参阅我们的[长训练示例](/docs/examples/long-training)
  检查点的实际演示。
* 确保抢占式操作可以安全地重试（即幂等）。

## 不可抢占函数
如果您需要保证不被抢占的功能，您可以设置`nonpreemptible`
参数（从客户端版本 v1.2.3 开始可用）到 `@app.function()` 或 `@app.cls()` 装饰器中的 `True`。
请注意，以下情况下，CPU 和内存使用量将应用 3 倍乘数到 [标价](https://modal.com/pricing)：
`nonpreemptible` 设置为 `True`。

**注意：** GPU 函数不支持 `nonpreemptible` 参数。

## 非抢占式沙箱

模态沙箱不受抢占的影响，除非`gpu`
要求已明确。这是因为可用性和调度延迟限制。
