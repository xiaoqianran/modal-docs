# 用户组

<Callout variant="gated-feature">
用户组需要<a href="/docs/guide/rbac">基于角色的访问控制
(RBAC)</a>，可在<a href="/pricing">团队和企业上使用
计划</a>。创建和管理组需要工作区所有者或
工作区管理员角色。访问<a href="/settings/plans">工作区设置</a>
升级。
</Callout>

<Callout variant="beta" />

用户组可让您同时管理多个工作区成员的访问权限。添加
成员到一个组，然后为该组分配一个环境角色
[受限环境](/docs/guide/rbac#setting-up-restricted-environments)
它需要访问。

## 组类型

Modal 支持两种类型的用户组：|团体类型|创建于 |名称和会员资格管理于 |
| ---------- | ---------- | ------------------------------------------ |
|定制|莫代尔|莫代尔 |
| SCIM |您的 IdP |您的 IdP |

您可以从模态将环境角色分配给任一类型的组。仅SCIM
控制群组的名称和成员资格；模态仍然是事实的来源
其环境访问。

## 创建自定义组

要创建并填充自定义组：

1. 打开[工作空间管理设置]上的**组**选项卡
   页面]（/设置/工作区管理/组）。
2. 单击“**创建组**”。
3. 输入组名称并选择要添加的工作区成员。
4. 单击“**创建**”。

可以在没有任何成员或环境访问权限的情况下创建组。分配一个
环境角色稍后将该角色应用于每个当前和未来的成员
团体。

## 更新自定义组

在 **组** 设置页面上，展开自定义组并单击 **编辑组**
重命名它或更改其成员资格。您也可以直接删除会员
从该组的成员列表中。

组成员资格的更改会更新成员对每个环境的访问权限
分配给该组。

## 使用 SCIM 管理组

启用 [SCIM](/docs/guide/scim) 组配置后，组推送
您的身份提供商 (IdP) 自动显示在 **组** 设置中
带有 **SCIM** 标签的页面。

管理 IdP 中 SCIM 组的名称和成员资格。这些字段不能
在 Modal 中进行编辑，因此 IdP 仍然是他们的真相来源。你仍然可以
在模态中分配、更改和删除组的环境角色。

从 IdP 中的组中删除用户会删除他们从其接收的访问权限
更改后的该组会同步到 Modal。停用或删除用户
通过 SCIM 还会根据您的 SCIM 删除他们的工作区访问权限
配置。

## Assign an Environment Role to a group

User groups work with [Role-Based Access Control
(RBAC)](/docs/guide/rbac) 在环境级别。 Groups do not receive a
工作区角色，并且不要更改可以管理工作区设置或计费的人员。

To assign a group to an Environment:

1. 打开[环境设置](/settings/workspace-management/environments)。
2. 单击受限环境的“**管理**”，然后打开“**访问”
   Restrictions**.
3. 选择“**组**”选项卡，然后单击“**添加组**”。
4. 选择自定义或 SCIM 组并选择环境角色：
   * **贡献者** — 可以查看和修改环境中的资源。
   * **查看者** — 可以查看资源，但不能修改它们。
   * **无法访问** — 无法发现或访问环境。
5. Click **Confirm**.

只能在受限环境中分配组角色。 From the same
**组**选项卡，您可以更改组的角色或从组中删除组
Environment. **组**设置页面还列出了每个环境和角色
assigned to each group.

## 组角色如何与其他 RBAC 设置相结合
工作区成员可以通过一个或多个直接接收环境角色
更多组，或来自受限环境的默认成员角色。莫代尔
解决这些来源如下：

* 任何直接或组角色优先于默认成员角色。
* 如果成员有多个直接或群组角色，则最宽松的角色
  适用：**贡献者**，然后是**查看者**，然后是**无访问权限**。
* 无论如何，工作区所有者和管理员始终拥有 **贡献者** 访问权限
  的小组作业。

例如，成员直接分配**查看者**并通过
组具有贡献者访问权限。 **无访问权限**组分配不会撤销
更宽松的直接或组分配，但它确实会覆盖环境
当没有其他显式分配适用时，默认为查看者或贡献者。

为了保持访问的可预测性，请将每个团队分配到其最小的组中。
在对成员的问题进行故障排除时，需要并检查直接角色和组角色
有效访问。
