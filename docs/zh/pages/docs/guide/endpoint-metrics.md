# 端点指标

每个端点都会报告实时推理指标，以便您可以了解其执行情况
在真实流量下——延迟、吞吐量以及正在进行的请求数量。
从 **Endpoints** 选项卡打开端点并转到 **Activity** 视图
看到他们。

有两种类型的可用指标：

* **推理指标** — LLM 引擎特定的指标，旨在为您提供更多信息
  性能可观察性。
* **服务器指标** — 标准 Modal 容器运行状况指标。

## 指标的含义

**延迟**（报告为 p50 / p95 / p99）：

* **第一个令牌的时间 (TTFT)** — 请求到达后多久
  第一个输出令牌流回来。用户首先感受到的数量。
* **令牌间延迟 (ITL)** — 连续输出令牌之间的平均间隙。
  提高感知的“打字速度”。
* **端到端延迟 (E2E)** — 完成请求的总时间。

**吞吐量：**

* **每秒请求数 (QPS)** — 请求到达率。
* **令牌吞吐量** — 令牌/秒，分为预填充（处理
  提示，用单独的一行表示缓存命中令牌）和解码（生成
  输出）。

**请求负载：**
* **请求活动** — 请求到达并完成的比率
  随着时间的推移终点。
* **正在运行** — 当前正在处理请求。
* **排队** — 请求等待空闲槽。持续排队意味着
  船队已饱和并正在扩大。

**推测解码**（仅适用于使用它的食谱）- 的平均数量
每步接受的草稿令牌；更高意味着投机正在获得回报。

## 注意事项

* **指标需要流量。** 延迟和吞吐量是根据最近的数据计算得出的
  滚动窗户；空闲或缩放至零端点不显示当前数据。
* **冷启动会导致早期数字出现偏差。** 扩大规模后的第一个请求
  包括模型加载时间。评估时查看稳态窗口
  性能。
* **百分位数需要数量。** p95/p99 仅在请求足够多时才有意义
  都堆积在橱窗里了
* 仪表板中提供了端点指标。获得可重复的性能
  受控负载下的数字，[运行
  基准](/docs/guide/endpoint-benchmarks)。
