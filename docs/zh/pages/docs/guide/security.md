# Modal 的安全和隐私

该文件概述了 Modal 的安全和隐私承诺。

## 应用程序安全（AppSec）

AppSec 是构建设计安全、安全的软件的实践
在开发过程中，通过测试和审查确保安全，并安全部署。

* 我们使用内存安全的编程语言（包括 Rust）构建我们的软件
  （对于我们的工作运行时和存储基础设施）和Python（对于我们的API
  服务器和模态客户端）。
* 软件依赖项由 Github 的 Dependabot 审核。
* 我们做出的决策会最大限度地减少我们的攻击面。大多数互动
  Modal 在 gRPC API 中得到了很好的描述，并通过
  [`modal`](https://pypi.org/project/modal)，我们的开源命令行工具
  和Python客户端库。
* 我们拥有自动化综合监控测试应用程序，可以持续
  检查运行时内的网络和应用程序隔离。
* 我们使用 HTTPS 进行安全连接。 Modal 强制所有服务使用 HTTPS
  TLS (SSL)，包括我们的公共网站和仪表板，以确保安全
  连接。 Modal的[客户端库](https://pypi.org/project/modal)连接
  通过 TLS 连接到 Modal 的服务器并验证每个连接上的 TLS 证书。
* 所有用户数据在传输和静态时均经过加密。
* 所有公共 Modal API 使用
  [TLS 1.3](https://datatracker.ietf.org/doc/html/rfc8446)，最新和
  最安全的 TLS 协议版本。
* 内部代码审查是使用现代的、基于 PR 的开发进行的
  工作流程（Github），并聘请外部渗透测试公司来评估我们的
  软件安全。

## 企业安全 (CorpSec)

CorpSec 是确保 Modal 员工能够安全访问
Modal 公司基础设施以及 Modal 的公开渠道
安全。 CorpSec 控制是 SOC2 等标准的主要关注点。

* 对我们的服务和应用程序的访问由 SSO 身份提供商控制
  （国内流离失所者）。
* 我们强制要求所有产品均采用防网络钓鱼的多重身份验证 (MFA)
  注册的 IdP 帐户。
* 我们定期审核对内部系统的访问。
* 员工笔记本电脑受到使用 FileVault2 的全磁盘加密的保护，并且
  由 Secureframe MDM 管理。

## 网络和基础设施安全 (InfraSec)

InfraSec 是一种确保强化、最小攻击面的实践
我们在网络上部署的组件。

* Modal 使用日志记录和指标可观测性提供程序，包括 Datadog 和
  Sentry.io。
* Modal 的计算作业使用容器化和虚拟化
  [gVisor](https://github.com/google/gvisor)，沙盒技术
  在 Google 开发并用于其 *Google Cloud Run* 和 *Google
  Kubernetes Engine* 云服务。
* 我们每年进行业务连续性和安全事件演习。

## 漏洞修复

直接影响Modal系统和服务的安全漏洞将被
在适合严重程度的时间范围内进行修补或以其他方式修复
漏洞的情况，取决于补丁或其他内容的公开可用性
补救机制。

如果漏洞披露附带 CVSS 严重性评级，我们
以此为起点，但可能会升级或降低严重性
使用我们的最佳判断。

### 严重性时间范围

* **重要：** 24 小时
* **最高：** 1 周
* **中：** 1 个月
* **低：** 3 个月
* **信息：** 3 个月或更长时间

## 共同责任模型

Modal 优先考虑客户数据的完整性、安全性和可用性。在我们的共同责任模型下，客户在数据备份、恢复和可用性方面也承担一定的责任。
1. **数据备份**：客户负责维护其数据的备份。建议执行每日备份。客户必须定期验证其备份的完整性。
2. **数据恢复**：客户应维护全面的数据恢复计划，其中包括在数据丢失、损坏或系统故障时进行数据恢复的详细程序。客户必须定期测试他们的恢复过程。
3. **可用性**：虽然Modal致力于高服务可用性，但客户必须实施应急措施，以在服务中断期间保持业务连续性。客户还应对自己的 IT 基础设施的可靠性负责。
4. **安全措施**：客户必须实施适当的安全措施，例如加密和访问控制，以在整个备份、存储和恢复过程中保护其数据。这些流程必须遵守所有相关法律和法规。

## 健康保险流通与责任法案
HIPAA 代表《健康保险流通与责任法案》，制定了一套保护健康信息的标准，包括个人医疗记录和其他可识别个人身份的健康信息。 HIPAA 准则适用于所涵盖的实体和业务伙伴 - 如果您在 Modal 上处理 PHI，则 Modal 是后者。

Modal 的服务可以以符合 HIPAA 的方式使用。值得注意的是，与其他安全标准不同，HIPAA 合规性没有官方认可的认证流程。相反，我们通过本文档中概述的实践、我们的技术和运营安全措施以及通过 SOC 2 认证等标准合规性的官方审核来证明我们遵守 HIPAA 等法规。
要将 Modal 服务用于符合 HIPAA 的工作负载，应在提交任何 PHI 之前与我们签订业务伙伴协议 (BAA)。这在我们的企业计划中可用。请通过 security@modal.com 联系我们以开始使用。目前，[卷 v1](https://modal.com/docs/guide/volumes)、[图像](https://modal.com/docs/guide/images)（不包括[文件系统和目录快照](/docs/guide/sandbox-snapshots)）、[内存快照](https://modal.com/docs/guide/memory-snapshots) 和用户代码超出了我们 BAA 的承诺范围，因此 PHI 不应在 BAA 的这些领域中使用产品。

[Volume v2](https://modal.com/docs/guide/volumes#volumes-v2) 符合 HIPAA 要求。

## PCI

*支付卡行业数据安全标准* (PCI) 是定义
支付卡处理的安全和隐私要求。

Modal 使用 [Stripe](https://stripe.com) 安全地处理交易并
相信他们对一流安全性的承诺。我们不存储个人信息
我们任何客户的信用卡信息。 Stripe 获得“PCI
服务提供商级别 1”，这是认证中的最高级别
支付行业。

## 数据隐私

Modal 永远不会访问或使用：

* 你的源代码。
* 模态函数的输入（函数参数）或输出（函数返回值）。* 您存储在 Modal 中的任何数据，例如图像或卷中。

应用程序日志和元数据存储在 Modal 上。 Modal 不会访问此数据
除非用户授予帮助排除故障的权限。

### 数据保留

不同的 Modal 产品对其数据有不同的保留策略
手柄。下表总结了每种类型数据的保留时间。

|数据|产品 |保留|
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
|输入和输出| [函数](/docs/guide)（`.remote`、`.spawn`、`.map`、[Web 函数](/docs/guide/webhooks)、计划函数）|最多7天，然后删除||请求和响应有效负载 | [服务器](/docs/guide/servers) 和 [自动端点](/docs/guide/endpoints) |不存储 - 直接代理到您的容器 |
|应用程序和容器日志 | [功能](/docs/guide), [沙箱](/docs/guide/sandboxes) |取决于计划：Starter 1 天，Team 30 天，Enterprise 上可配置（请参阅[定价](/pricing)）|
|审核日志|工作区（企业）|每个企业合同（请参阅[审核日志](/docs/guide/audit-logs)）|
|文件| [卷](/docs/guide/volumes)、[图像](/docs/guide/images) |持续存在直至您删除它们 ||内存快照 | [函数内存快照](/docs/guide/memory-snapshots)、[沙盒内存快照](/docs/guide/sandbox-snapshots) |创建后 7 天 |
|文件系统快照 | [沙盒文件系统快照](/docs/guide/sandbox-snapshots) |创建后 30 天（可配置；存储为图像）|
|目录快照 | [沙盒目录快照](/docs/guide/sandbox-snapshots) |创建后 30 天（可配置）|
|条目 | [字典](/docs/guide/dicts) |上次读取或写入后 7 天 ||隔断| [队列](/docs/guide/queues) |可配置的每个分区 TTL（默认 24 小时）|
|应用程序、功能和容器元数据 |所有产品 |在您的帐户的生命周期内存储 |

#### 函数输入和输出

函数输入和输出静态加密存储。有效载荷小
(≤ 2 MiB) 内联存储在我们的元数据存储中；存储更大的有效负载
在对象存储中。两者均会在最长 7 天的 TTL 内删除。

#### 模态推理端点

模态推理端点为零数据保留：请求和响应有效负载
永远不会写入磁盘，并且仅通过 Modal 的基础设施
飞行中的网络流量。推理端点在 Modal 边缘终止 TLS
代理并通过内部隧道将请求直接转发到您的容器。
