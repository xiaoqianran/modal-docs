# 对端点进行基准测试

实时指标告诉您端点在发生任何流量时的行为方式
得到。 **基准**告诉您它在已知的、
可重复加载 — 这样您就可以比较模型、区域和配置
同类基础上。

Modal 为您运行基准测试：它根据您的需求驱动标准负载生成器
来自沙箱的实时端点并报告结果。从一开始
端点详细信息页面上的 **基准** 选项卡。结果指标是
完成后可在仪表板中使用。

## 工作负载模式基准测试运行两种内置模式之一，每种模式的形状都不同
实际工作负载：

|图案|提示形状|型号|
| ------------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **实时生成** | ~3,000 个输入标记 → ~100 个输出标记，随机提示 |互动聊天/简答问答|
| **代理多转** | ~45,000 个令牌共享系统前缀 + ~5,000 个令牌问题 → ~200 个输出令牌 |具有长的、重复使用的上下文的代理/工具使用工作负载 |

代理模式在请求之间重用长共享前缀，因此它也
练习前缀缓存——代理工作负载性能的一个主要因素。

## 端点预览基准测试

当您在创建端点时选择模型时，您还会看到 **预先计算
基准**附加到模型的配方中。这些是参考号模态
在已知的 GPU 配置上进行测量，以便您可以比较候选模型
在部署任何东西之前。它们与上述基准有两个不同之处：
它们是由 Modal 提前生成的（不是针对您的端点运行），并且
它们与配方相关，而不是与您的具体部署相关。使用配方
选择模型的基准；运行您自己的基准测试来验证端点
您的区域和您的设置。

## 注意事项

* **基准发送真实流量。** 运行驱动您的实时端点、触发器
  自动缩放，并在运行时产生通常的计算成本。
* **结果为时间点。** 数字取决于当前机队规模，
区域，以及运行期间的任何冷启动。比较在类似情况下进行的运行
  条件，并让终点首先预热以获得稳态数据。
* **选择与您的用例相匹配的模式。** 实时且代理
  工作负载对服务堆栈的不同部分施加压力；基准测试
  错误的形状可能会产生误导。
